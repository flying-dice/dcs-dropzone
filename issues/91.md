## Summary
Automatically disable and clean up symlinks for 'inconsistent' mods. When the system detects symlink inconsistencies, the mod should be disabled automatically, all associated symlinks should be deleted, and the user should be notified. The user will be responsible for deciding when to manually attempt to re-enable the mod.

## Current Behavior
- 'Inconsistent' mods are identified passively with a status shown in the UI.
- Users must manually disable and re-enable mods to attempt reconciliation.
- Orphaned symlinks or dangling database references remain until manual intervention.

## Proposed Feature
1. **Automatic Disable:**
   - On detecting inconsistencies in symlink state (`installedPath` missing, references mismatched), the system will disable the problematic mod.
   - Set `enabled = false` and clear `installedPath` values from the database.
   - All symlinks related to the disabled mod will be removed.
2. **User Notification:**
   - Notify the user with a warning that the mod was disabled due to detected inconsistencies.
   - Provide an explanation in the UI so the user can review the affected mod and decide when (or whether) to re-enable it.

## UI/UX Changes
- Include a notification system (e.g., toast or banner) to inform users of automatic mod disablements.
- Display the status `DISABLED_BECAUSE_INCONSISTENT` in relevant sections of the UI.

## Acceptance Criteria
- [ ] Any mod marked `INCONSISTENT` due to symlink issues is automatically disabled.
- [ ] All symlinks associated with the inconsistent mod are removed.
- [ ] A user notification is displayed when a mod is disabled for this reason, explaining the cause and next steps.
- [ ] Code adheres to the current Ports & Adapters pattern for maintainability and testability.
